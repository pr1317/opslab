Four things a life-and-pensions back office needs from its data. The models were fitted in Python — pure standard library, no numpy or lifelines — and exported; this page evaluates them. Nothing is sent anywhere, and a parity test checks the arithmetic here reproduces the Python to 1e-9.

The operation

A simulated pensions back office: six months, five case types, a backlog surge injected part way through. Synthetic on purpose — it means the coefficients that generated it are known, so the estimates below can be checked rather than admired.

1 · The process, as the log actually ran it

Discovered from timestamps, not drawn from a procedure document. Green marks where cases start and red where they finish; dashed red edges point backwards, which in case management is exactly the rework. Real logs have a long tail of one-off paths — drag the slider to see how much of the map is noise.

2 · Is this week's number a change, or noise?

Weeks are bucketed by the date a case completed, not the date it arrived — bucketing by arrival puts finished and unfinished work in the same point and hides a growing backlog. Red points broke at least one Nelson run rule; hover for which.
